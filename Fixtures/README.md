# BicTerm Test Fixtures

Loopback-only fixtures for BicTerm's SSH transport, agent-forwarding, and
Coder-API tests. Nothing here touches the network beyond 127.0.0.1; all keys
are obviously fake (`bicterm-fixture-*`) and TEST-ONLY. The passphrase for the
encrypted fixture key is exactly `testpass`.

Bring everything up / tear it down:

```sh
scripts/fixtures-up.sh    # idempotent; runs self-checks; exits non-zero on failure
scripts/fixtures-down.sh  # kills daemons, verifies ports closed
```

Runtime state (pids, logs, the generated `ssh` wrapper) lives in
`Fixtures/run/` and is gitignored.

## Fixture blocks

### sshd (`Fixtures/sshd/`)

Two unprivileged OpenSSH servers, started with
`/usr/sbin/sshd -D -e -f <config> -h <hostkey> -E <log>`:

| name | port | config | host key | authorized_keys |
|------|------|--------|----------|-----------------|
| hop-1 (bastion) | 12222 | `hop1_config` | `host_keys/hop1_host_ed25519` | `authorized_keys_hop1` (ed25519, ed25519_passphrase, ed25519_hop2_unauthorized) |
| hop-2 (final)   | 12223 | `hop2_config` | `host_keys/hop2_host_ed25519` | `authorized_keys_hop2` (ed25519 only) |

Both: key-only auth (`PasswordAuthentication no`), `AllowTcpForwarding yes`
(needed for ProxyJump), `AllowAgentForwarding yes`, `PermitTTY yes`,
`LogLevel DEBUG3` with `-E Fixtures/run/hopN.log` (T9 provenance assertions
read these logs).

- **Alternate hop-1 host key** (T7 changed-host-key test): a second, distinct
  key lives in `host_key_alt/hop1_host_ed25519`, referenced by
  `hop1_config.alt`. Start hop-1 with it via `HOP1_ALT_KEY=1 scripts/fixtures-up.sh`.
  The active config is recorded in `Fixtures/run/hop1.active_config`.
- **macOS quirks**: all paths in the configs are absolute; `fixtures-up.sh`
  rewrites the path prefix to the current checkout each run, so moving the
  repo is safe. `StrictModes no` (fixture dirs lack strict perms),
  `UsePAM no`, `AuthorizedKeysCommand none` are required for an unprivileged
  sshd on macOS. Note macOS sshd unblocks the waiting loop after the FIRST
  TCP connect, so `nc -z` port-waits are reliable.

### Client keys (`Fixtures/keys/`)

Committed (deterministic for T3 parser golden tests) and regenerated by
`fixtures-up.sh` if deleted:

| key | type | passphrase | authorized on |
|-----|------|-----------|----------------|
| `bicterm-fixture-ed25519` | ed25519 | none | hop-1 AND hop-2 |
| `bicterm-fixture-ed25519_passphrase` | ed25519 | `testpass` | hop-1 |
| `bicterm-fixture-ed25519_hop2_unauthorized` | ed25519 | none | hop-1 ONLY (T9 second-hop auth failure) |
| `bicterm-fixture-rsa3072` | RSA 3072 | none | NOWHERE (T3 RSA-rejection parsing) |

### Agent protocol client (`Fixtures/agent/agent_client.py`)

python3-stdlib ssh-agent wire-protocol client. Runs INSIDE fixture SSH
sessions (e.g. `ssh -A ... 'python3 - list' < Fixtures/agent/agent_client.py`)
against `$SSH_AUTH_SOCK` to exercise BicTerm's forwarded agent (T8/T14):

- `list` — SSH_AGENTC_REQUEST_IDENTITIES, prints key types/comments
- `sign <pubkey-file> <data>` — SSH_AGENTC_SIGN_REQUEST (flags=0), prints signature hex
- `sign-raw <hex-frame> [chunk-size]` — sends an arbitrary COMPLETE frame
  (uint32 length + payload), optionally fragmented into chunk-size writes;
  torture/malformed-frame injection
- `flood <n> [pubkey-file]` — n rapid sign requests, prints ok/failed counts

Framing: uint32 BE length + payload. Opcodes: 11=request-identities,
12=identities-answer, 13=sign-request, 14=sign-response, 5=failure.

### Coder stub (`Fixtures/coder/stub.py`)

python3-stdlib HTTP stub on 127.0.0.1:18080. Requests logged to
`Fixtures/run/coder_stub.log`.

- `GET /api/v2/workspaces?q=owner:me[&limit=&offset=]` — requires header
  `Coder-Session-Token: fixture-token` (`expired-token`/missing/wrong →
  401 `{"message":"invalid api key"}`). Returns
  `{"workspaces":[...], "count":3}`: `dev-main` (running), `dev-api`
  (running), `batch-gpu` (stopped). `limit`/`offset` paginate (default 100).
- `POST /api/v2/users/me/keys/tokens` → 201 `{"key":"fixture-token", ...}`.
- `GET /api/v2/workspaceagents/{id}/connection` → minimal DERPMap stub (T20).
- `GET/POST /_control/mode` — runtime mode flips for T17 (no restarts):
  `ok` (default), `unauthorized` (401 on all authed endpoints),
  `ratelimited` (429 + `Retry-After: 1` on the NEXT request, then back to ok).

## The `ssh -J` wrapper (macOS quirk)

The acceptance two-hop command `ssh -o ... -J user@127.0.0.1:12222 ...`
spawns an implicit ProxyCommand child (`ssh -W ...`) that on this host
re-execs `/usr/bin/ssh` directly: it inherits NEITHER the parent's `-o`
flags NOR `$HOME` (OpenSSH uses getpwuid), so it cannot be pointed at a
project-local known_hosts/identity without writing to `~/.ssh` — which
these fixtures never do. `fixtures-up.sh` therefore generates
`Fixtures/run/bin/ssh`, a wrapper that translates `-J` into an explicit
`ProxyCommand` carrying the fixture options, and prepends
`Fixtures/run/bin` to PATH for its own self-check. To run two-hop CLI
checks by hand:

```sh
PATH="$PWD/Fixtures/run/bin:$PATH" ssh -o StrictHostKeyChecking=no \
  -o UserKnownHostsFile=/dev/null -J $(whoami)@127.0.0.1:12222 \
  -i Fixtures/keys/bicterm-fixture-ed25519 -p 12223 $(whoami)@127.0.0.1 true
```

The hop semantics are identical to real ProxyJump (stdio-forwarded SSH over
hop-1's direct-tcpip channel). BicTerm's own ProxyJump implementation (T9)
does not use the system ssh client and is unaffected by this.

## Adding a new fixture block

One directory per block under `Fixtures/<name>/`, plus:

1. A loopback-only daemon or tool, started from `scripts/fixtures-up.sh`
   (pidfile in `Fixtures/run/<name>.pid`, log in `Fixtures/run/<name>.log`,
   appended to the `Fixtures/run/pids` manifest).
2. A port-wait in the `wait_port` section and a loud self-check in the
   self-check section of `fixtures-up.sh`.
3. A new section in this README (keep the one-section-per-block structure)
   documenting ports, files, and which tasks consume it.
4. Any new bound port must stay loopback-only and be documented here.
